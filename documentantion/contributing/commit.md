# Правила коммитов

Формат: [Conventional Commits](https://www.conventionalcommits.org/).

## Структура

```
<тип>(<область>): <краткое описание>

<тело: что и почему изменилось, а не как>

<футер: Closes #123, BREAKING CHANGE: ...>
```

## Заголовок

- Формат `тип(область): описание`. Область опциональна.
- Длина до 72 символов.
- Повелительное наклонение: `add`, `fix`, `remove` (не `added`, `fixes`).
- Без точки в конце.
- Язык заголовка: английский.

## Типы

| Тип | Когда |
|---|---|
| `feat` | новая функциональность |
| `fix` | исправление бага |
| `docs` | документация |
| `refactor` | рефакторинг без изменения поведения |
| `test` | тесты |
| `chore` | сборка, зависимости, конфиги |
| `perf` | оптимизация |
| `ci` | CI/CD |

## Тело

- Нужно, только если причина изменения неочевидна.
- Отделяется от заголовка пустой строкой.
- Перенос строк на ~72 символах.
- Объясняет мотивацию и контекст, а не пересказывает дифф.

## Футер

- Ссылки на задачи: `Closes #123`, `Fixes #123`, `Refs #123`.
- Ломающие изменения: `BREAKING CHANGE: описание`.

## Правила

1. Один коммит - одно логическое изменение.
2. Не смешивать рефакторинг, фикс и новую функциональность.
3. Каждый коммит собирается и проходит тесты.
4. Не коммитить секреты, `.env`, артефакты сборки, закомментированный код.
5. Запрещены сообщения вроде `fix`, `wip`, `update`, `asdf`.

## Примеры

```
docs(readme): fix typo in install section
```

```
fix(auth): prevent token refresh loop on 401

Client retried refresh endlessly when the refresh request itself
returned 401. Now logout is performed after the first failure.

Closes #482
```
