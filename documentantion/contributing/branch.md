# Правила именования веток

## Формат

```
<тип>/<номер-задачи>-<краткое-описание>
```

- Номер задачи опционален, но желателен: `fix/482-token-loop`.
- Только строчные латинские буквы, цифры и дефисы. Слова разделяются `-`.
- Описание: 2-4 слова, отражает суть изменения.
- Длина имени до 50 символов.

## Типы

| Префикс | Когда |
|---|---|
| `feat/` | новая функциональность |
| `fix/` | исправление бага |
| `docs/` | документация |
| `refactor/` | рефакторинг без изменения поведения |
| `test/` | тесты |
| `chore/` | сборка, зависимости, конфиги |
| `perf/` | оптимизация |
| `ci/` | CI/CD |

Тип ветки совпадает с типом основного коммита в ней.

## Правила

1. Новая ветка создаётся от актуальной основной ветки (`main`).
2. Одна ветка - одна задача. Не смешивать несвязанные изменения.
3. Не работать напрямую в `main`.
4. Не делать `push --force` в общие ветки. В своей ветке только `--force-with-lease`.
5. После слияния ветка удаляется.

## Примеры

Хорошо:
- `feat/user-profile`
- `fix/482-token-loop`
- `docs/api-readme`

Плохо:
- `new-branch`, `test2`, `Fix_Bug`, `my-changes`
