# Правила оформления Pull Request

Шаблон описания: [.github/pull_request_template.md](../../.github/pull_request_template.md). GitHub подставляет его автоматически, заполни все секции.

## Размер и фокус

- Одна тема на PR.
- Желательный размер диффа до ~400 строк.
- Не смешивать рефакторинг и изменение поведения.

## Перед созданием

1. Ветка названа по [branch.md](branch.md).
2. Коммиты оформлены по [commit.md](commit.md).
3. Ветка актуализирована относительно основной (`rebase` или `merge`, как принято в проекте).
4. Тесты и линтер проходят локально.
5. Собственный дифф перечитан: нет отладочного кода, лишних файлов, секретов.

## Заголовок

Формат как у коммита: `<тип>(<область>): <описание>`.

Пример: `feat(search): add fuzzy matching`

## Правила

1. Незаконченную работу открывать как Draft PR.
2. Связывать с issue ключевыми словами: `Closes #123`, `Fixes #123`.
3. Неочевидные места поясняются комментариями в диффе.
4. На замечания ревьюера отвечать по существу и фиксить отдельными коммитами, пока идёт ревью.
5. Стратегия слияния (squash / merge / rebase) определяется правилами проекта.
6. После слияния ветка удаляется.
